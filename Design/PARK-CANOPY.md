# First PCG canopy pass

The saved park now contains 587 tree instances generated by an editable PCG graph. Ten retained stations come from individual OSM tree nodes; remaining stations are authored within mapped woodland, a lake-shore belt and the park boundary. These are not surveyed tree locations or a match to user photographs, which have not been supplied.

`Scripts/prepare_park_trees.py` deterministically constructs candidate stations in ESU using the existing geographic origin and scale. It excludes the water, path widths plus 180 cm, buildings, courts, pools, playgrounds, gardens, dog-park areas and the current frisbee clearings. Minimum spacing is 330 game cm. `Scripts/install_park_canopy.py` requires the converted park, traces every station onto Landscape, builds material bindings and creates a native PCG data asset/graph with a weighted static-mesh spawner. It verifies generated instance count before saving the map. It refuses to replace an existing canopy without review.

The interim tree mesh and seven textures come from the installed Epic Unreal 5.8 ArchVis template at `Templates/TemplateResources/Standard/ArchVis/Content/SampleScene/Tree`. Copied package paths are retained under `/Game/SampleScene/Tree`; rebuilt bark/leaf materials and PCG assets are under `/Game/BattleForTheA/Environment/Park`. Instanced-static-mesh material usage must be enabled before cooking. The original template material packages were not usable as copied and are not part of the authored canopy dependencies.

This is not the specified Megascans willow oak/magnolia/hardwood set. Species diversity, photo alignment, understory, grass, blossoms, leaves, wind and trunk collision remain unfinished. Canopy meshes deliberately have no collision; a broad leaf-canopy hull must never obstruct the path below it. Instancing and distance culling do not prove the 60 FPS requirement.
